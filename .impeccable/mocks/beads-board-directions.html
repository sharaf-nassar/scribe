A2 · Ledger + rail — A, with Blocked and Done collapsed to hover tabs

Blocked and Done are the only two queues that never arm a card drag, so collapsing exactly those two costs no gesture. They become 36px vertical tabs at the right edge. Hover opens a tab over the lanes; click pins it and the lanes give up real width — the same hover-opens / click-pins grammar the workspace bead already uses for the board itself. A tab holding work keeps its hue and count at full strength, so “4 blocked” still registers while collapsed. The label is one glyph per line rather than rotated text, because GPUI cannot transform a text element.

The head is a label row, not a bar. A filled 34px band spent a sixth of a 197px strip announcing five words; now one hairline and five aligned seams do the grouping, each label takes its own queue's hue pulled two thirds of the way to the chrome ink, the count drops to meta size and muted ink because the label already carries the identity, and the text-size steppers are two borderless glyphs on that line. Every pixel reclaimed went to the rows, which run 51px — the head is down to 12% of the strip and the work holds 78%. Each seam carries its hue at the lane's own start and lets go across it, so the five read as a direction rather than as five equal slabs.

The rest is measure and repetition. An empty queue no longer holds a full working column; a queue whose every issue shares one epic names it once in the head and drops it from the rows, the same reason the ID already drops the project prefix every card repeats — the hover drawer obeys the same rule. The sub line is three columns rather than one run-on string: ID left, age on the row's true centre, epic right, so the ages read as a column down the lane whether or not a row carries an epic. The count sits beside its name rather than at the far edge, an empty note starts where a title would, a lane holding more than it shows carries the board's own ⌄ mark, and the strip terminates in its own bar, which is the resize grip.

A3 · Flow — what opening a card lands on, and the graph the tracker actually stores

Every version above is a kanban: five buckets, and whatever order the rows happen to be in. But Beads is not a bucket tracker — it is a dependency graph, bd ready literally means “no active blockers,” and BeadsBoardItem already ships blocker_ids on the wire, which the card throws away. This epic is a real DAG: .1 forks into two branches that run in parallel, reconverge on .6, and end at .7. Five columns cannot say that. Flow ranks nodes by depth in the graph instead of by status, so “what is ready” stops being a query and becomes a position, and “what happens after this” becomes visible for the first time.

The second half is something no tracker can render and no terminal can either. bd records an issue's assignee, and Scribe knows which of its own panes is running that agent right now — so the live node gets a halo that means running here, not merely assigned. The board stops reporting what somebody remembered to set and starts reporting what the machine is doing.

Flow is where opening a card lands. Clicking a row in Lanes no longer just raises a panel over the terminal — the strip itself becomes that card's epic, with the clicked issue marked as the cursor. Answering “why can I not start this?” stops being a read of a blocker list and becomes a position: the card sits one hop right of the node a machine is on. Lanes and Flow are two modes of one board rather than two designs, so returning is the same control that got you here, and a card with no epic keeps today's behaviour and opens the panel instead.

The node is sized by the budget, not the other way round. The strip is a fixed 197px and spends it exactly: band 34 + ruler 15 + graph 139 + hbar 2 + gap 4 + floor 3. Everything else derives from a node compact enough to leave the graph room, which means the old sub line folds into the title line and the node carries dot, priority, title and id on one 214×24 row:

rank pitch    = node width 214 + gutter 28 = 242px
row pitch     = node height 24 + row gap 10 = 34px
rows per rank = floor((139 + 10) / 34) = 4

The gutter is two 14px stubs either side of the dogleg, so every fork leaves its source and enters its target on the same 1px rails at each rank. Four rows is the whole point of the exercise: the previous 262×40 node on a 56px row pitch fitted two, so any rank wider than that had nowhere to go. Depth costs width instead — eight ranks is 30 + 7×242 + 214 = 1938px against a 1552px strip — and width is the axis that can scroll. The wheel moves x, the clipped side fades into the ground so a cut rank reads as continuing rather than ending, and a 2px bar reports position. No state shows a vertical scrollbar and none is meant to: the graph is ranked into the band's own height, so there is never anything below to scroll to.

Text scale moves the node but not the reservation, so the row budget is a function of scale and worth stating rather than discovering: floor((139 + 10s) / 34s) gives 5 rows at 0.8, 4 at 1.0 and 2 at 1.6. Folding the sub line away is what keeps that workable — a two-line node at 1.6 would leave a single row. A rank too wide for the budget at the current scale is the layout engine's admission problem, not something to solve by growing the strip.
